## Conditional full-mode loader exposure and static risk

The configured `SHOP_FILE` is `areas/world.shp` ([definition](../../../src/world/db.h#L22)), and that aggregate is absent in this checkout. Outside mini mode, [`open_shop_stream`](../../../src/economy/shop.c#L3267) falls back to concatenating `areas/shp/*.shp`, skipping `end.shp` before appending the terminator. That fallback can include `ddguild.shp` and `player_guilds.shp`, even though neither is named by the full `areas/AREA` manifest. The [SHP aggregate builder](../../../areas/src/shp/make_shp.c#L26) reads the `AREA` manifest at its working directory and opens only the listed shop files, rather than globbing the whole shop directory. This is conditional source-code exposure, not proof that a server or shop was run.

The current full-area source set has no mobile #35300 and no object #35301: their only same-type definitions are in `asunwa.mob` and `asunwa.obj`, and those files are outside the full area list. `real_mobile()` and `real_object()` return -1 for absent VNUMs ([mobile lookup](../../../src/world/db.c#L8587), [object lookup](../../../src/world/db.c#L8655)). `boot_the_shops()` stores those lookup results, and the boot sequence later calls `assign_the_shopkeepers()` ([call site](../../../src/specs/specs.assign.c#L1258)); the assignment code indexes `mob_index[keeper]` without a negative-index guard. If the non-mini fallback is exercised with this source set, this is a static boot-safety risk from unresolved keeper #35300, not a confirmed crash or runtime result. The unresolved product and room references also need qualification before any loader or shop-use claim.
