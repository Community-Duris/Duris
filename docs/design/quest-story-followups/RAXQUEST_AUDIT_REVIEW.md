## Story and exact QST mirror

Raxquest QST has 13 giver records and 31 contracts: 24 QA directives and seven Q directives. Warthehr Ngolahn's story asks for eight sword fragments and a hilt, sends the party through several named areas, has Telrar reforge the weapon in Kimodril, and then asks for Aghalhassax's daughter and her skin from a ghost ship. Other records cover the auction gadget, Milerg's wolf, the ogre-gnome's yo-yo, Derimous's four-horned antelope, and Abal/Lyle's scepter thread. These are QST texts and item rows; they do not establish working routes or loaded quest contracts. See [the opening contract](../../../areas/qst/raxquest.qst#L1), [Telrar and the dragon hunt](../../../areas/qst/raxquest.qst#L150), and [the Abal/Lyle records](../../../areas/qst/raxquest.qst#L371).

The 462-line Raxquest QST is an exact normalized line-for-line copy of both [FooQuest QST](../../../areas/qst/fooquest.qst#L1) and [Black Pearl QST](../../../areas/qst/blackpearl.qst#L1): replacing local 650xx, 705xx, and 142xxx numeric VNUM tokens with one placeholder makes every line equal; 362 lines are already identical without normalization. Each file has 13 corresponding giver IDs in its own numeric set. The exact copy is strong QST-level lineage/reuse evidence. It does not show that FooQuest or Black Pearl replaces the Raxquest WLD, MOB, OBJ, or ZON identity. FooQuest is also absent from the full AREA list, and none of these three per-stem QST sources is named in qst/AREA. Resolve which source and generator are authoritative before copying, loading, moving, or removing any QST.

Raxquest contains 88 R/G item-reference rows over 39 distinct VNUMs. All but one point to Raxquest OBJ prototypes. The exception is R I 26201 at [raxquest.qst line 384](../../../areas/qst/raxquest.qst#L384). Current [Moonshae OBJ #26201](../../../areas/obj/moonshae.obj#L9) is the shimmering key; the Black Pearl QST has the same numeric row, and its [story sidecar](../../../areas/story/blackpearl.story.json#L11) connects the key to Abal's scepter thread. ## Compiled code/data mismatch

Raxquest code remains in the build: [src/Makefile](../../../src/Makefile#L721) includes specs/specs.raxquest.o. [specs.assign.c](../../../src/specs/specs.assign.c#L1494) assigns nine object callbacks to Raxquest OBJ VNUMs and thirteen mobile callbacks to Raxquest MOB VNUMs. It also unconditionally assigns [ship_shop_proc to room #70501](../../../src/specs/specs.assign.c#L2384). That shared procedure is implemented in [ship_shop.c](../../../src/ships/ship_shop.c#L2960); it is not a Raxquest SHP record.

The assignments use real_object0, real_mobile0, and real_room0. The [lookup helpers](../../../src/world/db.c#L8401) return index 0, rather than -1, when a requested VNUM is absent; the specific [room](../../../src/world/db.c#L8480), [mobile](../../../src/world/db.c#L8553), and [object](../../../src/world/db.c#L8621) helpers implement that fallback. Since no current active same-type table contains the Raxquest VNUMs, the source has an unguarded compiled binding to a missing data identity. The code comments describe index 0 as protection against a negative array index, not a successful binding. Without running the boot path, this audit does not claim which index-0 state would result or whether some external build supplies matching data. Preserve the data/code mismatch for explicit code, loader, and deployment-owner review.

## Checkpoint 927: cross-type IDs keep separate source and code roles

The WLD, MOB, and OBJ files reuse most of the same numeric VNUMs, but each is a separate typed identity: 62 values (#70500–#70503 and #70505–#70562) occur in all three tables; #70504 occurs as a room and mobile only; #70563–#70583 occur as room and object; and #70584–#70598 occur as objects only. For example, #70501 is the WLD room “A Gaping Hole in the Side of a Pirate Ship,” a MOB “pirate tough,” and an OBJ “brittle brass key” ([room](../../../areas/wld/raxquest.wld#L6), [mobile](../../../areas/mob/raxquest.mob#L12), [object](../../../areas/obj/raxquest.obj#L9)). Treat these as role-qualified numbers; an untyped numeric match does not resolve a prototype.

The full `areas/` literal scan found no standalone 705xx reference outside the five Raxquest files. The 98 Raxquest OBJ records contain no item type 25 (`ITEM_TELEPORT`) or 29 (`ITEM_SWITCH`), matching the constants for [ITEM_TELEPORT](../../../src/core/defines.h#L140) and [ITEM_SWITCH](../../../src/core/defines.h#L144). No Raxquest SHP, story sidecar, or QST aggregate is present in this checkout; the QST `AREA` still does not list Raxquest. These findings add no external portal, switch, shop, sidecar, or quest consumer and do not change the current zero active WLD inbound count.

The exact `src/` literal scan found Raxquest VNUMs only in [specs.assign.c](../../../src/specs/specs.assign.c#L1494) and the dedicated [specs.raxquest.c](../../../src/specs/specs.raxquest.c#L157), which is included in the build by [src/Makefile](../../../src/Makefile#L721). `specs.assign.c` retains nine `real_object0` callbacks, thirteen `real_mobile0` callbacks, and `ship_shop_proc` on room #70501. Those are type-specific bindings even when a VNUM overlaps: for example, object #70554 and mobile #70554 receive different callbacks in separate tables. The dedicated Raxquest code binds the shout behavior to mobile #70535, checks and summons mobile #70536, and lists mobile helpers #70536–#70541, #70547, and #70548. Its `read_mobile` branch checks for a null result, but this static source does not prove that the callback or any Raxquest mobile is loaded or reached.

The room procedure on #70501 does not create an SHP catalog, and none of these code references repairs the absent full-area prototypes. The `real_*0` index-0 fallback and unregistered data remain an unresolved code/loader/deployment concern. Keep all five files RETAIN IN PLACE; this checkpoint adds no route, alias, lineage, or migration clearance.
